# Astro MCP とサイト改善（2026-09-14）

## リポジトリ内のMCP設定

`.codex/config.toml` でAstro公式ドキュメントMCPに接続する。
グローバル設定やWebサイトの依存パッケージを変更せず、このプロジェクトで利用する。

```toml
[mcp_servers.astro-docs]
url = "https://mcp.docs.astro.build/mcp"
```

`codex mcp get astro-docs` で認識を確認済み。
MCPのinitialize、tools/list、search_astro_docsを実際に呼び出し、検索結果を取得済み。
実行中の会話にツールが追加されない場合は、プロジェクトを開き直すか新しい会話から利用する。
検索内容にAPIキーや下書き本文は含めない。

MCPはAIが資料を調べるための仕組みであり、訪問者のブラウザでは実行されない。
このリポジトリのAstroは **5.13.10**。検索結果に含まれる新しいバージョンの機能は、導入済みバージョンに対応しているか確認してから使う。

公式資料: https://docs.astro.build/en/guides/build-with-ai/

## 1. 表示速度・画像・スプラッシュ

- ヒーロー・記事カバーは優先取得、一覧画像は遅延読み込み。
- ローカル画像と仮サムネイルは表示幅別のWebPを生成。仮画像は約18KBから2.8 / 4.6 / 7.0KBのバリエーションへ。
- microCMSの画像CDNに限り、表示幅別URLと圧縮指定を生成する。
- ローカルの指定画像が見つからない場合は仮画像へフォールバック。
- ハッシュ付きの `/_astro/` アセットには長期キャッシュを設定。
- 現行ページにスプラッシュや表示待ち演出はない。本文をすぐ読める設計を維持する。

Core Web Vitalsの本番実測値は今回計測していない。実ユーザーのLCP/INP/CLSはデプロイ後に確認する。

## 2. SEOと構造化データ

- robots.txtで画像・CSS・JavaScriptのクロールを許可。
- noindexのプレビューとページ番号付き一覧をサイトマップから除外。
- 共通OGPの画像をサイトの仮サムネイルへ統一。
- WebSite / PersonのIDとサイト説明を統一し、記事にBreadcrumbListを追加。
- JSON-LD内のCMS由来テキストに `</script>` が含まれてもHTMLとして解釈されないようエスケープ。
- microCMS本文のh1はh2へ変換し、ページタイトルだけをh1にする。

構造化データの整備は、サイトリンクや検索表示を保証するものではない。

## 3. microCMS取得・エラー・プレビュー

- 1回の取得は8秒でタイムアウト。通信障害、429、5xxを本番ビルドでは最大2回、プレビューでは最大1回再試行。
- 401/404などの恒久エラーは再試行しない。エラーにAPIキー・下書きキー・上流レスポンスを含めない。
- ビルド中は取得済みの記事一覧を共有し、ページごとの重複リクエストを減らす。
- 接続設定が存在するのに取得に失敗した場合、本番ビルドを停止する。ローカル記事だけの不完全なデプロイを防ぐ。
- キーとサービス名の片方だけの設定もエラーにする。両方未設定のローカル環境ではMarkdown記事だけでビルド可能。
- ページングの件数変化、欠落・重複、危険なslug、不正日付を検出する。slug未設定の公開記事は修正してから再ビルドする。
- プレビューのURLから下書きキーを除去する既存動作を維持。再試行に必要な値は開いている画面のメモリにのみ保持する。ブラウザ再読込時はmicroCMSから開き直す。
- エラー時に「もう一度読み込む」を表示し、no-store / noindex / no-referrerを維持する。
- microCMS公開から本番反映までは従来どおりCloudflare Pagesの再ビルドが必要。

このローカル環境には実サービスのキーがない。APIとブラウザのプレビュー検証はテスト用データを使用し、本番サービスの公開・下書き取得やWebhookは変更していない。

## 4. 共通部品とサイト固有設定

- `src/config/site.ts`: サイト名、公開URL、運営者名、共通説明、仮画像、フッター導線、広告枠。
- `src/data/projects.ts`: 各アプリ固有の画像・説明・配信先。
- `ProjectCard.astro`: アプリを表示する共通部品。
- `src/scripts/editor-tabs.ts`: 公開記事とプレビューで共通のタブ操作。
- `src/lib/microcms-request.mjs`: ビルドとCloudflare Functionで共通のAPI取得。
- APIキー・計測IDなどは従来どおり環境変数で設定する。

個人ブログのため会社切替機能は設けず、再利用するUIからサイト固有値を分離した。
別ドメインへ移す場合は `functions/_middleware.js` の転送先、Cloudflareのドメイン設定も合わせて更新する。

## 5. アクセシビリティとモバイル

- ボタン・フォーム・折りたたみなどにもキーボードフォーカス表示を適用。
- 長い目次を折り返し、狭い画面で項目の内容を読めるようにする。
- プレビューのタブでも左右矢印・Home/Endで切替できるよう修正。
- ストアリンクは読み上げ時にアプリ名と新しいタブで開くことを伝える。
- プレビューの読み込み・失敗を通知し、JavaScript無効時は案内を表示。

## 検証

```sh
pnpm check
pnpm test:site
pnpm build
```

ローカルブラウザでは390px幅のトップ・記事の横はみ出し、遷移と戻る、主要リンクの44px以上の操作領域を確認。
テスト記事でプレビューの取得失敗→再試行→本文・装飾の表示、タブの矢印キー操作、320px幅の横はみ出しがないことを確認。
設定不正時の本番ビルド停止も別の一時出力ディレクトリで確認。

プレビューをテストデータで再確認する場合は、通常ビルド後にそれぞれ別のターミナルで実行する。

```sh
pnpm preview --host 127.0.0.1 --port 4325
node tests/fixtures/preview-server.mjs
```

`http://127.0.0.1:4326/preview/#contentId=qa-article&draftKey=test-only` を開く。
サーバー起動後の初回は意図的に取得を失敗させ、画面の再試行ボタンから復旧を確認できる。
このサーバーは127.0.0.1だけで待ち受け、本番のAPIキーを使わない。
