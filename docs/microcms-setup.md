# microCMS運用ガイド

## 方針

既存のMarkdown記事はそのまま残し、新規記事からmicroCMSへ切り替えます。記事一覧、アーカイブ、関連記事、RSSでは両方をまとめ、同じURL設計・記事カード・SEO情報を使います。microCMSが一時的に取得できない場合は、既存のMarkdown記事だけでビルドを継続します。

## 1. APIを作る

作成済みのサービスは `tumolog`、リスト形式のAPI IDは `blogs` です。記事本体には次のフィールドがあります。

| フィールドID | 種類 | 必須 |
| --- | --- | --- |
| `title` | テキストフィールド | はい |
| `content` | リッチエディタ | いいえ |
| `eyecatch` | 画像 | いいえ |
| `category` | コンテンツ参照 | いいえ |
| `slug` | テキストフィールド | はい |
| `description` | テキストエリア | いいえ |
| `tagsText` | テキストエリア（1行に1タグ） | いいえ |
| `blocks` | 繰り返しフィールド | いいえ |

`content`（表示名「記事本文」）が普段使う執筆欄です。文章を選択してツールバーの「カスタム」から、マーカー、囲み、ボタン、吹き出し、FAQをその場で適用できます。表はテーブル、SNS・動画・一般URLは埋め込みボタンから本文内へ直接追加できます。

`blocks`（表示名「高度なブロック」）は、商品画像と複数ストアURLを持つ商品紹介など、リッチエディタだけでは情報が足りない場合に使います。通常の記事では使わなくて構いません。以前の並べ替え形式も互換性のため残しています。

`blocks` では、STORK19系のブログカード、SNS・動画埋め込み、装飾画像、2カラム、タブ切り替えも選択できます。URLを貼るだけの埋め込みはYouTube、X、Instagram、TikTok、Vimeoに対応しています。入力項目の一覧は `docs/editor-blocks.md` を参照してください。

## 2. Cloudflare Pagesへ秘密情報を登録する

ローカルでは `.env.example` をコピーして値を入れます。本番ではCloudflare Pagesの環境変数に次を登録します。

```text
MICROCMS_SERVICE_DOMAIN=サービスドメインの先頭部分
MICROCMS_API_KEY=GET権限だけを持つAPIキー
MICROCMS_API_ENDPOINT=blogs
```

`MICROCMS_API_KEY` に `PUBLIC_` を付けるとブラウザへ公開されるため、付けません。

## 3. 公開時の自動デプロイ

Cloudflare PagesでDeploy Hookを作り、そのURLをmicroCMSのWebhookに登録します。記事の公開・更新を契機に本番サイトを再ビルドします。

## 4. 記事を公開する

1. `ブログ` から記事を追加します。
2. `タイトル` と英数字の `URLスラッグ` を入力します。
3. `記事本文`へ文章を書き、装飾したい箇所を選択してツールバーの「カスタム」から見た目を選びます。
4. 公開するとWebhook経由でCloudflare Pagesが再ビルドされます。

既存Markdownと同じslugを入力した場合は、記事データを守るためMarkdown版が優先されます。ブログテンプレート付属のサンプルはslugが空なのでサイトには表示されません。

## 5. 公開前にプレビューする

`ブログ` APIの「画面プレビュー」には次のURLを登録します。

```text
https://tumolog.com/preview/#contentId={CONTENT_ID}&draftKey={DRAFT_KEY}
```

記事編集画面の「画面プレビュー」を押すと、公開前の本文・アイキャッチ・カテゴリ・タグ・装飾ブロックを本番サイトと同じデザインで確認できます。下書きキーはURLのハッシュからすぐ消去し、ブラウザには保存しません。プレビュー取得はサーバー側で行い、APIキーをブラウザへ公開しない構成です。プレビューページは検索対象・アクセス解析・広告配信から除外しています。
# リアルタイム本文エディター（追加機能）

`blogs` のAPIスキーマに、任意の拡張フィールドを追加します。

- フィールドID: `liveBody`
- 表示名: `本文とリアルタイムプレビュー（試用）`
- 拡張フィールドURL: `https://tumolog.com/editor/`
- 必須: オフ

入力した本文を、その場でサイトの本文スタイルで確認できます。入力データはmicroCMSのフォームに送信されますが、サーバーへの確定保存ではありません。画面を閉じる前にmicroCMSの「下書きを保存」を押してください。タイトル・メタ情報を含むページ全体の確認には従来の「画面プレビュー」を使います。

初期状態は「この編集欄を記事の本文に使う」がオフです。オンにして保存した記事だけ、新しい本文を使用します。既存の `content` と `blocks` は変更も削除もしません。従来の本文を移す場合は、まずコピーして表示を確認してください。リッチテキストの貼り付けでは未対応の埋め込みや書式は引き継げない場合があるため、確認前に旧本文を削除しないでください。

新エディターでは本文中の挿入位置を選び、「商品ボックスを挿入・編集」から商品名・リンクを入力して挿入できます。挿入済みの商品ボックスをクリックすると内容を編集できます。PCは左右表示、スマホは「表示」を「編集のみ」「プレビューのみ」に切り替えて使えます。

## 従来の本文欄で、文章の途中に商品ボックスを置く

1. 「高度なブロック」→「フィールドを追加」→「商品紹介」を選び、商品名とAmazonなどのリンクを入力します（表示名は管理画面の設定によります）。
2. 「かんたん本文」で挿入したい場所に空の段落を作り、`[[product:1]]` だけを入力します。コード書式や太字は付けません。
3. 保存して画面プレビューを開きます。1つ目の商品紹介がその場所に入り、末尾には重複しません。2つ目なら `[[product:2]]` です。番号は商品紹介だけを数えます。

`p90vucrmch` では、AQUOSへの既存リンク `https://amzn.to/4isplle` を商品紹介のAmazon URLに使えます。この記事は移行・書き換えを行っていません。従来の「本文」ブロックを使って順番を組んでいる記事では、引き続きブロック自体を並べ替えてください。

## Amazon商品画像

**自動取得は未接続です。** Amazon Creators APIの利用資格と認証情報を確認できるまで、画像取得処理は稼働させません。現状は利用権のある画像をmicroCMSの画像欄（新エディターでは画像URL欄）に指定します。画像がなくても商品名とリンクは表示できます。

公式資料:

- [Creators APIの前提条件](https://affiliate.amazon.co.jp/creatorsapi/docs/en-us/introduction)
- [認証とGetItems](https://affiliate.amazon.co.jp/creatorsapi/docs/en-us/get-started/using-curl)

連携時は認証情報をCloudflareのサーバー側シークレットに保存し、クライアントやCMS記事には保存しません。商品画像は公式APIから得たURLを使用し、キャッシュ期間などのライセンス条件を守って更新します。APIの利用資格がない場合、商品ページのスクレイピングや推測URLで代替しません。
